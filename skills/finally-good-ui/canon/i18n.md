# Internationalisation

Scope: everything that changes with the reader's language, region or script: formats of dates, times, numbers and currencies, plurals, text length, direction and the language the interface chooses. Applies even to single-language apps: their users still live in many locales.

### i18n.locale-formats

```yaml
id: i18n.locale-formats
domain: i18n
principle: "Format dates, times, numbers, currencies, lists, plurals and relative times with Intl in the user's locale (account setting, else navigator.languages; never IP geolocation). Never hard-code patterns such as MM/DD/YYYY or 1,000.00, and give server and client the same explicit locale and time zone."
why: "03/04 is March 4 to some readers and 3 April to others; a hard-coded format is wrong for most of the world. Formatting with different defaults on the server and in the browser also makes hydrated pages flicker or mismatch."
sources: ["ECMA-402, ECMAScript Internationalization API", "Unicode CLDR", "W3C Internationalization, Language tags and locale identifiers", "Vercel, Web Interface Guidelines (locale and i18n)"]
applies-when: "Any displayed date, time, duration, number, currency, percentage, list or count."
not-when: "Machine-readable values: ISO 8601 in APIs and datetime attributes, CSV exports, identifiers."
decides: [copy.numbers, component.date-display]
tensions: [typography.tabular-numbers]
asked-by: []
checks:
  measured: "check-static locale-format: no toLocale*String() without a locale, no hard-coded date patterns."
  judged: "Would a reader in another country read every date and number on this screen correctly?"
```

### i18n.text-expansion

```yaml
id: i18n.text-expansion
domain: i18n
principle: "Lay out for text that grows: labels, buttons and nav items take their width from content (no fixed widths around text), wrap or truncate deliberately with the full text available on hover and to screen readers, and survive strings 30-40% longer than English and very long user content (names, emails, URLs) with min-width: 0 on flex children and overflow-wrap: anywhere."
why: "German and Finnish run far longer than English, and real user content runs longer than sample data. Fixed boxes clip or overlap the moment either arrives, usually after launch."
sources: ["W3C Internationalization, Text size in translation", "IBM Globalization, Guidelines for text expansion", "Vercel, Web Interface Guidelines (long content)"]
applies-when: "Every component that holds text, and every list, table or card showing user content."
not-when: "Fixed-format values (codes, tabular figures) where width is part of the meaning; still let them wrap on narrow screens."
decides: [component.button, component.nav, component.table]
tensions: [layout.grid-alignment, data.dense-tables]
asked-by: []
checks:
  measured: "Render with pseudo-localised text (+40%) and a very long name, email and URL: no clipped or overlapping text, no horizontal page scroll."
  judged: "What happens to this screen when every string is a third longer?"
```

### i18n.direction-logical

```yaml
id: i18n.direction-logical
domain: i18n
principle: "Write layout in logical terms so the interface mirrors for right-to-left scripts: margin-inline-start, padding-inline, inset-inline-end, text-align: start, and Tailwind's ms-/me-/ps-/pe-/start-/end-; set dir and lang on <html>; mirror icons that point along the reading direction (back, next, send) and leave the rest (play, checkmarks, logos)."
why: "Arabic, Hebrew, Persian and Urdu readers number in the hundreds of millions. Physical left/right CSS has to be rewritten to support them; logical CSS mirrors for free and costs nothing in left-to-right pages."
sources: ["CSS Logical Properties and Values Level 1", "W3C Internationalization, Structural markup and right-to-left text in HTML", "Material Design, Bidirectionality"]
applies-when: "All new layout CSS, and any product that may ship in a right-to-left language."
not-when: "Things tied to physical space rather than reading order: maps, media controls, charts' time axes in some locales (check the locale's convention)."
decides: [layout.css, component.icon]
tensions: [layout.grid-alignment]
asked-by: []
checks:
  measured: "Static: physical margin-left/right, padding-left/right and left/right in new layout code are counted; render with dir=rtl and compare."
  judged: "With dir=rtl on <html>, does the screen read correctly from the right, with arrows pointing the right way?"
```

### i18n.language-choice

```yaml
id: i18n.language-choice
domain: i18n
principle: "Choose the interface language from the account setting, else Accept-Language / navigator.languages, never from IP location; let people change it in one obvious place, named in its own language (Deutsch, not German); set lang on <html> and on any passage in another language; mark brand names, code and user content translate=\"no\" so browser translation leaves them alone."
why: "Location is a poor guess at language (travellers, multilingual countries, VPNs), and a wrong guess with no visible way back locks people out. lang drives screen-reader pronunciation, hyphenation and font fallback."
sources: ["W3C Internationalization, Language on the Web and the lang attribute", "WCAG 2.2 SC 3.1.1 Language of Page and 3.1.2 Language of Parts", "Vercel, Web Interface Guidelines (locale and i18n)"]
applies-when: "Any app with more than one language, and every app's <html lang> and translate attributes."
not-when: "Single-language internal tools still set lang; skip the switcher."
decides: [blueprint.settings, component.language-switcher]
tensions: [usability.user-control-undo]
asked-by: []
checks:
  measured: "Probe: <html lang> is set and matches the content; brand names and code are translate=\"no\"."
  judged: "Could someone who lands in the wrong language find their own in one step?"
```
